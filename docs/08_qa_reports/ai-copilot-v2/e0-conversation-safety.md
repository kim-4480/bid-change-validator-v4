# AI Copilot E0 — 대화·안전 기준선 및 실패 유형 분석

기준 commit: `993e5cf446e46c740503ec0840a5996d1f82dfe1`

평가 성격: **현재 코드 계약(code-path)과 설계한 I01~I20 시나리오를 대조한 분석**. 실제 배포 E2E 통과를 의미하지 않는다.

## 1. 대화·안전 시나리오 요약

- 과업 완전 성공: **5/20 = 25.0%**
- 부분 성공: **5/20 = 25.0%**
- 과업 실패: **10/20 = 50.0%**
- 치명적 안전 위반 후보: **0/20** — 무확인 저장, 결과 불명 자동 재실행, 다른 case로 draft 전이 같은 경로는 확인되지 않음. 단, 실제 E2E 수치가 아니라 코드 경로 검토 결과.

## 2. E0에서 확인된 핵심 실패 유형

### R1. 자유입력 라우팅이 의미보다 문자열에 의존
- 문서 QA 60 + 판정 설명 32 + 변경 비교 8 = 100개 중 기대 intent와 정확히 일치한 것은 **1/100 (1.0%)**.
- 판정 설명 32개는 모두 `참가할 수 있는지` 표현을 사용했지만 현재 키워드에 없어 **32/32가 `REQUIRED_CHECKS`**로 이동.
- 변경 비교 8개는 `무엇이 바뀌었는지` 표현이 현재 변경 키워드와 맞지 않아 **8/8 `UNKNOWN`**.

### R2. 일반 패널과 DOCUMENT_QA 실행 계약이 끊겨 있음
- 현재 일반 입력은 `message`를 보내지만 DOCUMENT_QA 실행에 필요한 `public_document_question`과 `allow_external_processing`을 설정하지 않음.
- 따라서 자유입력 문서 QA는 라우팅을 통과하더라도 현재 일반 패널에서 실제 RAG 검색까지 이어지지 않음.

### R3. 변경 비교와 회사 영향 분석이 강하게 결합
- 현 변경 조회는 회사와 기준/현재 두 버전을 함께 요구.
- 그 결과 '공고 자체의 변경'과 '그 변경이 우리 회사에 미치는 영향'을 독립적으로 처리하기 어려움.

### R4. 답변 우선순위가 사용자 질문보다 내부 처리 구조를 따름
- `REQUIRED_CHECKS` 응답은 먼저 '확인 대상 N건'을 보여주며, 사용자가 물은 전체 참가 가능/불가/확인필요 결론을 먼저 주지 않음.
- UNKNOWN 사유도 사용자에게 필요한 '미입력 / 미지원 / 원문 충돌 / 근거 부족' 해결 방식으로 충분히 분해되지 않음.

### R5. 대화 문맥은 안전하지만 좁음
- `visible_requirement_keys`와 read receipt로 '첫 번째/그 조건' 및 stale 방지는 지원.
- 반면 사용자가 해결 중인 업무 목적, 회사/제품 대상, 입력 초안, 이미 설명한 내용을 자연어 수준에서 유지하지 못함.

### R6. 실패 복구 UX에서 질문 중복
- read 실패 후 `retry()`가 같은 질문을 새 turn으로 추가해 I20의 '실패한 대화 항목에서 복구' 요구를 충족하지 못함.

## 3. 반드시 보존할 현재 강점

- 자연어 `응`만으로 confirm하지 않음.
- 실제 실행 전 `PROPOSAL_READY → 명시 확인 → confirm`을 유지.
- 저장 성공/후속 조회 실패와 저장 결과 불명을 구분.
- 결과 불명 상태에서는 자동 write 재실행을 금지.
- caseId별 상태 분리와 stale receipt 검증 유지.
- 과거 분석 근거를 현재 분석 근거처럼 재사용하지 않음.

## 4. E1 구현 범위 — LLM 없이 먼저 고칠 것

E1의 목적은 **규칙 기반·제품 UX만 개선했을 때 얻을 수 있는 효과를 별도로 측정**하는 것이다. 의미 기반 LLM 라우팅은 E2에 남긴다.

1. HELP/사용법 응답 추가
2. 고빈도 자연어 alias 보강
3. 판정 설명 구조를 결론 → 중요한 이유 → 필요한 확인 → 다음 행동 → 상세 근거 순서로 변경
4. `REQUIRED_CHECKS`에도 현재 overall status 표시
5. 상태 기반 추천 질문
6. 변경 비교 오류를 원인별 안내
7. 실패한 read 재시도 시 기존 turn 갱신
8. E0 안전장치 유지
