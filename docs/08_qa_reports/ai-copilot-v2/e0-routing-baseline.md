# E0 Copilot 자유입력 라우팅 기준선

- 기준 commit: `993e5cf446e46c740503ec0840a5996d1f82dfe1`
- 범위: `route_intent()`의 **자유입력 텍스트 라우팅만** 측정. 추천 버튼처럼 프론트가 `intent`를 명시해서 보내는 경우, DB 조회, RAG 검색, 최종 답변 품질은 이 수치에 포함하지 않음.
- 평가셋: Copilot 120개 초안 중 현재 8개 intent와 일대일 매핑 가능한 문서 QA 60 + 판정 설명 32 + 변경 비교 8 = 100개.

## 결과

| 묶음 | N | 기대 intent 정확 일치 | 주요 실제 라우팅 |
|---|---:|---:|---|
| 문서 QA | 60 | 1/60 = 1.7% | UNKNOWN 43, REQUIRED_CHECKS 13, QUALIFICATION_SUMMARY 2, DOCUMENT_QA 1, ACTION_REQUEST 1 |
| 판정 설명 | 32 | 0/32 = 0.0% | REQUIRED_CHECKS 32 |
| 변경 비교 | 8 | 0/8 = 0.0% | UNKNOWN 8 |
| **합계** | **100** | **1/100 = 1.0%** | UNKNOWN 51, REQUIRED_CHECKS 45 등 |

## 해석

- 문서 QA 60개 중 43개(71.7%)가 `UNKNOWN`으로 떨어졌고, 정답 라우팅 `DOCUMENT_QA`는 1개뿐이었다.
- 판정 설명 32개는 모두 `REQUIRED_CHECKS`로 라우팅됐다. 질문의 `참가할 수 있는지`는 현재 제품 진실 키워드 목록에 없고, 뒤쪽의 `확인할 내용`이 먼저 잡혀 판정 요약이 아니라 확인목록으로 흐르는 패턴이다.
- 변경 비교 8개는 모두 `UNKNOWN`이었다. `무엇이 바뀌었는지`는 현재 변경 키워드(`뭐바뀌`, `뭐가바뀌`, `변경된요건` 등)에 걸리지 않는다.
- 따라서 이 1.0%는 **Copilot 전체 정확도**가 아니라 '사용자가 버튼의 정해진 표현 대신 자기 말로 입력했을 때 현재 규칙 라우터가 평가 의도와 정확히 일치한 비율'이다.

## 대화·안전 20개 첫 입력 도달성

- 텍스트 첫 입력이 있는 19개 중 `UNKNOWN` 11개 (57.9%), 비-UNKNOWN 라우팅 8개 (42.1%).
- 이는 성공률이 아니라 **라우터 도달성 상한**이다. 비-UNKNOWN이어도 후속 행동 검증이 별도로 필요하다.

## 정적 코드 경로 기준 작업 완결 가능성

이 항목은 실제 DB/API E2E가 아니라 현재 고정 코드의 라우팅과 요청 계약을 따라가며, 시나리오가 요구한 핵심 결과까지 도달 가능한지를 본다.

- 문서 QA 60: **0/60**. 59개는 `DOCUMENT_QA`로 가지 않는다. 유일하게 `DOCUMENT_QA`로 간 질문도 일반 패널 요청에는 `public_document_question`과 `allow_external_processing`이 없으므로 Backend가 실제 검색 답변 대신 별도 질문/동의 안내를 반환한다.
- 판정 설명 32: **직접 판정 결론 경로 0/32**. 모두 `REQUIRED_CHECKS`로 가고, 해당 presentation의 결론은 `저장된 판정의 확인 대상 N건입니다`이며 `overall_status`에 대한 직접 결론을 표시하지 않는다.
- 변경 비교 8: **0/8**. 모두 `UNKNOWN`이라 변경 비교 도구가 호출되지 않고 기본 unsupported 응답으로 끝난다.

따라서 100개 핵심 자유입력 시나리오 중 **요청한 전체 작업 계약을 정적으로 충족하는 경로는 0/100**이다. 이 값 역시 최종 답변 정확도가 아니라, 현재 UI/Backend 계약에서 자유입력이 목표 기능까지 도달 가능한지 보는 '작업 도달성/완결성 기준선'이다.
