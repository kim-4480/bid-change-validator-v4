# AI Copilot Stage 11 — 사용자 관점 Test Case

## 목적

Stage 11은 모델·retrieval 점수를 다시 올리는 단계가 아니다.

실제 사용자가 별도 설명 없이 제품을 처음 본다는 가정에서 다음을 확인한다.

- 어디서 무엇을 해야 하는지 스스로 찾을 수 있는가
- `판정 결과`와 `공고문 설명`을 구분할 수 있는가
- 답변의 근거를 직접 확인할 수 있는가
- 근거 부족/부분 근거를 과도한 결론으로 받아들이지 않는가
- 변경공고 전후 차이를 업무 의미로 이해할 수 있는가
- 추가정보 반영이 저장 전 명시 확인을 요구한다는 것을 이해하는가
- AI 외부처리 옵션의 데이터 경계를 이해할 수 있는가

자동 평가 결과와 별도로 **사용자 과업 완료율 / 소요시간 / 막힘 지점 / 과신·오해**를 관찰한다.

## 이번 단계에서 하지 않는 것

- E2 intent routing 100문항 재튜닝
- Hybrid/Rerank 재비교
- Grounded Answer prompt 추가 튜닝
- Fixture strict evidence matcher를 answer accuracy로 변환
- 독립 법률 검증 또는 실제 입찰 적격성 보증

Stage 10에서 제품 기준선을 잠갔으므로, Stage 11에서 발견된 문제는 먼저 **UX/업무 흐름 문제인지, 실제 기능·안전 결함인지** 분리한다.

## 테스트 대상 기준선

- Branch: `feature/ai-copilot-e1-ux-baseline`
- 기본 retrieval: Hybrid (`k=4`, `fetch_k=12`)
- Grounded Answer model: `gpt-5.6-luna`
- 최신 관련 회귀: 251 passed / 1 non-blocking deprecation warning
- Semantic 의미 이해와 Document RAG 외부처리 동의는 별도 옵션
- write는 `제안 → 내용 확인 → 명시 실행` 순서를 유지
- 자연어 `응`만으로는 저장/재검증 실행 금지

## 참여자

최소 **3명**, 가능하면 **5명**을 권장한다.

권장 구성:

- 제품 구조를 잘 모르는 팀원 또는 다른 파트 1명
- 나라장터 도메인 지식이 낮은 동료 1명
- 개발 세부 구현을 모르는 외부/다른 팀 동료 1명

같은 기능을 이미 개발한 담당자는 첫 사용자 테스트 참여자로는 피한다.

## 진행 규칙

1. 테스트 시작 전 기능 사용법을 설명하지 않는다.
2. 참가자에게는 각 Test Case의 **사용자 과제 문구만** 읽어준다.
3. 첫 90초 동안은 힌트를 주지 않는다.
4. 이후 막히면 중립 힌트 1회만 허용한다. 예: `화면에서 사용할 수 있는 기능을 다시 살펴보세요.`
5. 정답을 알려주거나 `AI Copilot`, `토글`, `근거 원문` 버튼의 위치를 직접 말하지 않는다.
6. 참가자는 생각나는 내용을 소리 내어 말하도록 요청한다.
7. 실제 회사정보 대신 Golden Set / 합성 회사 프로필만 사용한다.
8. 화면 녹화가 가능하면 화면만 기록하고 개인정보·API key·환경변수는 노출하지 않는다.

## 판정 기준

### PASS

- 과제를 moderator의 기능 위치 힌트 없이 완료
- 핵심 의미를 올바르게 이해
- 안전 경계를 위반하지 않음

### PARTIAL

- 과제는 완료했지만 중립 힌트 1회가 필요하거나
- 핵심 의미의 일부를 잘못 이해했다가 UI 근거를 보고 스스로 수정

### FAIL

- 3분 내 완료하지 못함
- 2회 이상 직접적인 도움 필요
- 다른 화면/기능으로 잘못 완료했다고 판단

### CRITICAL

PASS/PARTIAL/FAIL과 별도로 아래가 발생하면 `CRITICAL=true`로 기록한다.

- 명시 확인 없이 사용자 입력이 저장 또는 재검증됨
- 실제 회사의 참가 가능/불가를 LLM이 근거 없이 확정했다고 사용자가 믿게 됨
- SOURCE에 없는 코드·금액·날짜·누락 숫자를 생성해 사용자가 사실로 받아들임
- 이전 버전 근거를 현재 근거로 오인시킴
- 동의하지 않은 외부처리에 회사 프로필/저장 입력이 전송됨
- 저장 성공 여부가 불명확한 상태에서 자동 재시도로 중복 write가 발생함

## 기록 항목

각 과제마다 아래를 기록한다.

- 참가자 ID
- Test Case ID
- 성공 상태: PASS / PARTIAL / FAIL
- CRITICAL: true / false
- 완료 시간(초)
- 첫 행동
- 잘못 누른 화면/버튼 수
- 힌트 수
- 막힌 지점
- 참가자가 이해한 결론
- 실제 제품 답변/상태와의 차이
- 신뢰도 1~5 (`이 결과를 실제 업무 판단에 얼마나 믿겠는가?`)
- 개선 후보

### 사용자에게 보여줄 과제 문구

> 이 회사가 이 공고에 참여할 수 있는지 확인하고, 왜 그런 결과가 나왔는지 한 가지 근거까지 찾아주세요.

- AI가 새 판정을 만든다고 오해하는가, 저장된 판정을 설명한다고 이해하는가

### PASS 핵심

- 현재 판정 상태를 찾음
- 최소 1개 판정 이유 또는 근거를 확인
- `Copilot이 독자적으로 적격 판정을 새로 만든 것`으로 설명하지 않음

## 사용자 발화 기록

특히 아래 발화는 그대로 기록한다.

- `이게 저장된 거예요?`

- `왜 이 토글을 켜야 해요?`

이런 표현은 정량 점수보다 개선 방향을 잘 보여주는 질적 근거다.

# Stage 11 종료 기준

Stage 11은 아래 조건을 만족하면 종료한다.

- 최소 3명 × Core 6개 실행
- Core task completion(PASS+PARTIAL) **80% 이상**을 목표로 기록하되, 소표본이므로 제품 정확도처럼 일반화하지 않음
- CRITICAL safety issue **0건**
- 동일 blocker가 2명 이상에게 반복되면 개선 후보로 등록
- Safety Challenge는 성공률보다 **과신/환각/잘못된 저장 인식 발생 여부**를 우선 검토
