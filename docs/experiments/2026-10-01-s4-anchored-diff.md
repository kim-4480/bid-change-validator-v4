# S4: 원문 조항 기준 차수 비교 (2026-10-01)

러너: `eval/experiments/diff_probe.py` (gpt-6-luna, 추출 결과를 먼저 저장하고 `--reuse` 로 재계산할 수 있다).

## 바꾼 것 (`bidengine/diff/requirement_diff.py`)

1. **같은 자리의 요건이 여럿일 때도 짝짓는다.** 정체성(유형 + 원문 뼈대)이 같은 요건이 여럿이면(한 조항의 대안 묶음) 판정 내용이 같은 것끼리 먼저 UNCHANGED, 남은 것은 값 순서대로 MODIFIED 로 짝짓는다. 예전에는 하나씩일 때만 짝지어 나머지가 추출 순서 키로 떨어졌다.
2. **항목 번호는 내용이 아니다.** 조항 앞의 번호·기호("4)", "가.", "ㅇ")를 무시한다. G2 2차에서 강원도 조항(2번)이 빠지자 뒤 항목 "4) … 1169" 가 "3) … 1169" 로 당겨졌다.
3. **설명용 scope 는 판정 내용이 아니다.** `industry_name`·`source_name`·`guard` 를 비교에서 뺀다. 업종 요건은 코드로 판정하는데, 모델이 표시용 업종 이름을 실행마다 다른 길이로 잘라 왔다.

추출 방식은 `BIDENGINE_EXTRACTION_MODE`(legacy | clause, 기본 legacy)로 고른다. 전환은 배포 설정으로 한다.

## 결과

### 같은 공고를 다시 추출해 비교 (공고 4건 × 형식 2 × 3회, 쌍 24개) — 전부 UNCHANGED 여야 한다

| 추출 | 차수 비교 | 오탐률 | 내역 |
| --- | --- | --- | --- |
| legacy | 이전 | 0.639 | 수정 22 / 추가 27 / 삭제 27 / 변경 없음 43 |
| legacy | 새 | 0.310 | 수정 15 / 추가 8 / 삭제 8 / 변경 없음 69 |
| clause | 이전 | 0.207 | 수정 5 / 추가 10 / 삭제 10 / 변경 없음 96 |
| **clause** | **새** | **0.096** | 수정 3 / 추가 4 / 삭제 4 / 변경 없음 104 |

### 실제 변경공고 G2 (1차 → 2차, 제안요청서의 "강원도 본점" 조항 삭제)

1차·2차 각 3회 추출, 9쌍 비교. 정답은 쌍마다 **강원도 지역 요건 삭제 1건 + 업종 1169 변경 없음 1건**이다.

| 추출 | 차수 비교 | 결과 (9쌍 합계) | 정답 쌍 |
| --- | --- | --- | --- |
| legacy | 이전·새 | 삭제 16 / 추가 7 / 변경 없음 2 | 0/9 |
| clause | 이전 | 삭제 9 / 수정 9 | 0/9 (1169 를 수정으로 봄) |
| **clause** | **새** | **삭제 9 / 변경 없음 9** | **9/9** |

- 처음 실행에서는 공고문 PDF 만 넣어 강원도 조항이 아예 추출되지 않았다. 그 조항은 **제안요청서 6쪽**에 있다. 제품은 한 차수의 문서를 모두 분석하므로 러너도 공고문 + 제안요청서를 함께 넣도록 고쳤다.
- legacy 는 강원도 삭제를 잡기는 하지만, 모델이 원문을 매번 다르게 인용해 다른 요건까지 추가·삭제로 흔든다.

## 결론

조항 단위 추출 + 새 차수 비교에서 변경공고 대조가 처음으로 실사용 수준(오탐 0.10, 실제 변경 9/9)에 닿았다. 기본값 전환(`BIDENGINE_EXTRACTION_MODE=clause`, `OPENAI_MODEL_DEFAULT=gpt-6-luna`)은 표본 확대 비교 뒤에 한다 — 나라장터(`apis.data.go.kr`, `www.g2b.go.kr`) 접속이 환경 네트워크 정책에 막혀 있다.
