ADR 0001의 구조 문제 중 LLM 없이 재현할 수 있는 2·4·5·6을 현재 엔진 코드로 쟀다. 재현 스크립트는 `eval/experiments/structural_diagnosis.py`이고, DB·API 키 없이 돈다.

```bash
python eval/experiments/structural_diagnosis.py --out artifacts/diagnosis.json
```

추출 단계가 필요한 문제 1(구조를 모델이 정함)과 3(표현력), e2e 측정(S0)은 `OPENAI_API_KEY`가 있어야 잰다.

## 문제 2: 요건 정체성이 원문 문자열이다 — 확인됨

골든 v0.2의 요건 138개를 1차 공고로 두고, **의미는 그대로인** 2차 공고를 만들어 `diff_requirements`를 돌렸다. 이상적인 결과는 기존 138개가 전부 UNCHANGED다.

| 2차 공고 변형 | UNCHANGED | 오탐 (MODIFIED / REMOVED / ADDED) |
| --- | --- | --- |
| 줄바꿈·공백만 다름 | 138 (100%) | 0 / 0 / 0 |
| 인용에 각주 한 줄이 붙음 | 0 (0%) | 138 / 0 / 0 |
| 인용에서 ※·괄호 주석이 빠짐 | 75 (54%) | 63 / 0 / 0 |
| 앞에 요건 1개 추가(순서 밀림) | 79 (57%) | 36 / 23 / 23 |
| 각주 붙음 + 순서 밀림 | 0 (0%) | 50 / 88 / 89 |

- 공백 정규화는 제 역할을 한다. 로컬 진단의 "줄바꿈 위치에 흔들릴 위험"은 현재 코드에서는 재현되지 않는다.
- **인용 경계**(모델이 각주를 붙이거나 주석을 빼는 것)는 전부 MODIFIED가 된다. `decision_payload`가 정규화한 raw를 비교하기 때문이다. MODIFIED는 재검증 대상이고 이전 답변을 이어받지 못한다.
- **순서 밀림**만으로 요건의 43%가 오탐된다. `semantic_identity`가 유일하지 않으면(같은 유형·같은 raw 뼈대) 추출 순서 키로 떨어지고, 앞에 요건이 하나 끼면 키가 전부 한 칸씩 밀린다.
- 결론: 원문 앵커 정체성(S4)의 근거가 확실하다. 특히 "각주 붙음 + 순서 밀림"은 실제 변경공고에서 흔한 조합인데 정답률이 0%다.

## 문제 4: 열린 어휘를 문자열 포함으로 판정한다 — 확인됨, 교정안 시험

골든 J06 조항("2년 내 2개 이상 단체급식소를 1년 이상 운영한 실적")을 추출기가 채우는 모양(`>= 2`, 24개월, 경험분야 "단체급식 운영")으로 두고, 기간 안 실적 2건을 가진 회사의 **실적 표기만** 바꿔 판정했다.

| 회사 실적 표기 | 현재 | 교정 후 |
| --- | --- | --- |
| 단체급식 운영 | 충족 | 충족 |
| 급식 운영 | 충족 | 충족 |
| 단체급식소 위탁운영 | **미달** | 확인 필요 |
| 집단급식소 운영 | **미달** | 확인 필요 |
| 위탁급식 | **미달** | 확인 필요 |
| 구내식당 운영 | **미달** | 확인 필요 |
| (자격 없음) 청소 용역 | 미달 | 확인 필요 |
| (자격 없음) 시설 경비 | 미달 | 확인 필요 |

- 현재: 자격 있는 회사 **4/6을 미달로 오판**한다. "적합 프로필이 미달 5/5"와 같은 현상이다.
- 골든 게이트로는 이 문제가 안 보인다. 골든의 해당 요건은 연산자가 비어 있어 처음부터 보류로 빠진다.
- 교정(실험 브랜치): 기간 안 실적이 **경험분야·발주처 문자열 비교로만** 빠졌으면 미달 대신 확인 필요로 둔다. 기간 안 실적 자체가 없으면 여전히 미달이다.
  - 효과: 오판 4/6 → 0/6. 골든 110/28/0 그대로, 전체 테스트 통과.
  - 대가: 자격 없는 회사의 **올바른 미달 2/2도 확인 필요**가 된다. 통제 어휘(S6)가 생기면 되찾는다.
  - 기존 테스트 하나(`해외진출` 분야 요구 + `정보시스템 구축` 실적 → 부적격)를 새 정책에 맞춰 고쳤다. 정책 변경이므로 팀 합의가 필요하다.

## 문제 5: PARTIAL이 전체 적합을 막는다 — 확인됨, 로컬 교정안은 위험

- 합성: 충족 요건 1개 → `SUCCEEDED`면 적합, `PARTIAL`이면 확인 필요. 진단대로다.
- 요건 0개 + `SUCCEEDED` → 판정은 이미 확인 필요다. 문제는 판정이 아니라 **분석 상태가 SUCCEEDED로 보고되는 것**(커버리지 부재)이다.
- **골든 40건이 전부 PARTIAL이고, 기대값에 적합이 한 건도 없다.** 골든 게이트는 이 문제를 원리상 볼 수 없다(문제 7의 사례).
- PARTIAL 차단을 빼면 J27 한 건이 확인 필요 → **적합**으로 바뀐다. 골든은 J27을 "공고 전체 검수 미완료"라 확인 필요로 본다. 즉 "적합 여부는 요건 판정만으로 결정"하는 로컬 교정안은 커버리지 없이 적합을 선언하는 위험한 방향이다.
- 결론: PARTIAL 전역 차단은 **커버리지 지표로 대체**해야지 그냥 제거하면 안 된다. 적합은 "자격 절을 찾았고, 그 안의 후보가 모두 요건으로 변환됐다"가 확인될 때만 준다.

## 문제 6: 문서 모델이 없다 — 확인됨

실데이터셋(qualification-real-v0.1)에서 **같은 공고문**을 HWP/HWPX와 PDF로 각각 넣고 청킹·자격절 선별을 비교했다.

| 케이스 | 형식 | 블록 | 청크(제목 인식) | 선별 청크 | 선별 글자 | 선별 안 쪽 번호 줄 | 낱말 중간 줄바꿈 | 두 형식 선별 일치도 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| C01 | HWPX | 98 | 12 (11) | 1 | 509 | 0 | 0 | **0.19** |
| C01 | PDF | 7 | 3 (**0**) | 2 | 2,749 | 6 | 55 | |
| C02 | HWP | 97 | 11 (10) | 1 | 319 | 0 | 2 | 0.70 |
| C02 | PDF | 5 | 16 (15) | 1 | 324 | 0 | 3 | |
| C03 | HWP | 187 | 75 (74) | 22 | 1,720 | 0 | 26 | 0.85 |
| C03 | PDF | 6 | 75 (74) | 21 | 1,651 | 2 | 26 | |
| C04 | HWPX | 348 | 187 (185) | 83 | 6,731 | 0 | 39 | 0.79 |
| C04 | PDF | 17 | 190 (189) | 80 | 5,386 | 0 | 96 | |

- PDF는 쪽 하나가 블록 하나다(평균 640~1,030자). C01 PDF는 **제목을 하나도 인식하지 못해** 자격 절 대신 키워드 폴백으로 5배 넓은 본문을 모델에 넘기고, 그 안에 쪽 번호 줄 6개와 낱말 중간 줄바꿈 55개가 섞인다.
- 같은 공고인데 형식에 따라 모델이 받는 입력의 일치도가 0.19~0.85로 흔들린다. 모델 출력이 흔들리는 원인의 일부가 모델 밖에 있다는 뜻이다.
- 결론: 블록 역할을 가진 문서 모델(S2)이 먼저다. 코드 주도 조항 열거(S3)와 앵커(S4)가 그 위에서만 성립한다.
